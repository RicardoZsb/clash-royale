# 皇室战争 UI 还原

主场景：`Assets/Scenes/ClashRoyaleUI.unity`。也可从 Unity 菜单「Clash Royale UI → 打开还原场景」打开。

设计来源：Figma `Nbp7FeVnTaPPgSxHbdgL8e`，FigJam `9nTVfktj7MUHDJW9ioE667`。快照读取时间：2026-10-26。10 页原稿均以 402 × 874 为参考尺寸。

## 调整界面

- 选中 `ClashRoyaleCanvas / Interface · 402 × 874`，Inspector 底部提供全部页面的预览按钮，编辑模式即可切页。
- 每页都保存为 `Prefabs/Screens` 下的独立预制体。文字是 TextMeshProUGUI；底板、描边、图片是 Image；可点击区域是 Button；列表使用 ScrollRect、Mask、LayoutGroup 和 ContentSizeFitter。
- `Prefabs/Components` 提供战令奖励行、部落成员行、战令概览、顶部切换栏、底部导航、宝箱组合、聊天输入框。调整实例后可按 Unity 常规流程 Apply 到预制体。
- 对象上的 `FigmaLayer` 保存原稿节点编号和名称。也可以在 Hierarchy 搜索方括号内的编号。
- `Art` 是原稿独立图标和插画，`Art/Generated` 是圆角、描边、渐变和裁切 Sprite。没有把整页截图当作界面。
- 圆角底板和描边使用九宫格 Sprite，可以直接调整 RectTransform 尺寸和 Image 颜色。更改列表项目数量时，编辑 Content 下的现有行或复制行；布局组件负责排列。
- CanvasScaler 使用 Scale With Screen Size / Expand，参考尺寸 402 × 874。完整设计区域在屏幕中央等比缩放；宽高比不同时保留外侧留边，避免导航、文字和图标互相挤压。

## 已连接的界面关系

- 底部交叉双剑进入战斗主页，部落盾牌进入部落主页。
- 战斗主页的任务、战令、宝箱入口，进入对应页面；这三个页面的顶部页签互相切换。
- 部落主页进入商店、竞赛、聊天；各页左上和右上图标按关系图切换。
- 宝箱队列展示服务端队列的前三只宝箱，可逐只点击开启；开启后下一只自动补入现有位置。点击领取画面的背景返回队列。
- 战令共 40 级，等级、经验、奖励和领取状态读取服务端；「一键领取」领取已达成且未领取的免费奖励。未开通付费战令时右侧保持锁定，皇冠入口显示未开通提示。
- 聊天页右下绿色聊天按钮进入输入页；输入文字后按蓝色上箭头返回聊天页，显示本条本地消息。
- 部落商店左侧分类按钮切换选中颜色。任务列表读取配表文字，商品内容区保留原型。

## 本机数据接入（2026-11）

配表：`Assets/Tables/ClashRoyale_V5.4.xlsx`；业务代码：`Assets/Scripts/Runtime`；编辑器工具：`Assets/Scripts/Editor`。

任务卡片预制体为 `Assets/Prefabs/Components/TaskCard.prefab`。三角收起只显示简述，展开显示详情；接取后展开才有部落求助按钮。任务数据由本机后端与 SQLite 保存。

接取后自动激活；战斗主页紫色卷轴旁的下拉列表调整自动激活规则，任务页分类下拉仅控制显示排序。展开后的“强制激活”可优先安排一条任务，“取消强制”恢复自动规则。任务底板按一级浅蓝、二级浅绿、三级浅紫、特殊浅金区分，配色在 `UITaskCard` Inspector 中调整。主页宝箱入口仅在队列非空时显示左侧延伸底板和红点；空队列保留圆形图标，仍可点击进入队列。

点击 Play 时，编辑器自动检查并启动本机后端，界面在服务就绪后连接。菜单「Clash Royale → 本机后端联调」仍可手动启动服务、重新导入 Excel、提交模拟对局。完整数据库和启动说明见项目根目录 `Backend/README.md`。

## 原型与接入范围

任务、行动点、宝箱和战令数据已接入本机服务。账号、支付、真实战斗服务器及跨用户网络聊天仍未接入。商店、卡组、锦标赛等未提供目标画板的底部图标保留视觉样式；不虚构对应页面。

项目的界面脚本不会在场景启动时创建 UI GameObject，也不会通过 Instantiate 组装页面。`Runtime` 中的代码只控制已有对象、文字和 Sprite；`Editor` 下的首次导入器只供明确执行菜单时创建资产，已有主场景时会拒绝覆盖。

原始 `Assets/Scenes/SampleScene.unity` 保留。`DesignReference`（项目根目录）保存设计上下文、结构快照和关系图，供逐项对照。

## 验证记录

### 任务分类与激活方式下拉列表（2026-10-29）

- 任务页面的分类入口：`TaskSortDropdown`，提供「按等级 ↑」「按等级 ↓」「按完成度分类」。
- 战斗主页的紫色任务数量入口：`TaskActivationDropdown`，提供「按等级 ↑」「按等级 ↓」「按完成度」，保留任务图标和数量。
- ↑ 表示等级从低到高，↓ 表示等级从高到低，完成度表示从高到低。
- 面板从入口下方展开；选择后收起，点击面板外部关闭，切换页面也关闭。任务页排序在本次运行期间保留；主页激活规则存入本机数据库，重新运行后恢复。
- 两个组件预制体位于 `Prefabs/Components/`，面板、选项按钮和透明关闭区域均已保存为 uGUI 对象；运行时只切换显示和选择状态。
- 行为脚本为 `Scripts/Runtime/UIRuleDropdown.cs`。`SelectedRule` 提供当前规则，`On Rule Selected (Int32)` 事件可接入后续任务逻辑；0 = 等级升序、1 = 等级降序、2 = 完成度降序。现在按所选规则排序任务或向服务端请求自动激活；不在客户端直接扣除行动点。
- `Popup/OptionsPanel/Options` 中可调整三项按钮的文字、间距和高度；`Popup/OutsideClickToClose` 是透明关闭区域。`Scripts/Editor/AddTaskRuleDropdowns.cs` 只供编辑器首次添加，不会在游戏启动时生成界面。
- 已通过 Unity EventSystem 射线检测与按钮事件验证 10 项交互。记录位于 `DesignReference/Validation/task-dropdown-checks.json`，展开截图为 `TaskSortDropdown-Open.png` 和 `TaskActivationDropdown-Open.png`。桌面鼠标自动化未完成，未将其计为实测。
